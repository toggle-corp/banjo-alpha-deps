# Conventions

- **Helm chart changes require unit tests.** When adding or modifying values, templates, or rendered output in `chart/`, add a corresponding assertion in `chart/tests/*_test.yaml` (run with `helm unittest chart`). Exceptions: pure refactors that don't change rendered output, comment/whitespace-only edits.
- **Helm chart changes require a docs update.** When values, features, or rendered behavior change in `chart/`, update `docs/usages.md` (option reference, examples, and — if relevant — the alpha overlay section). Exceptions: internal refactors with no user-visible change (helper renames, comment-only edits).
- **Generated secrets use the bootstrap-Job pattern — no `lookup`, no `ignoreDifferences`.** Credential Secrets that default to empty are created/managed by a **pre-install/pre-upgrade Helm-hook `Job`** that runs `kubectl` against the **live cluster** (`chart/templates/tcpg/secret-bootstrap-job.yaml`, `chart/templates/minio/secret-bootstrap-job.yaml`), backed by shared auto-created RBAC (`chart/templates/secret-bootstrap-rbac.yaml`). This is one GitOps-safe mechanism for plain Helm, Flux-HelmRelease, and ArgoCD: there is **no `lookup`** (blind under `helm template`) and **no `ignoreDifferences` hatch**. Rules for such Jobs:
  - Use **only** `helm.sh/hook: pre-install,pre-upgrade` (weight `0`; RBAC at `-5`). Do **not** add `argocd.argoproj.io/hook` — ArgoCD auto-converts the Helm hook to `PreSync`, and an explicit Argo hook would suppress the Helm-hook path and break plain Helm/Flux (a Job spec is immutable). Do **not** apply `commonAnnotations` to these hook resources.
  - Compute static fields at **render time** (passed as env) and keep the existing `required`/`fail` validations in the Job template so render-time misconfig still fails closed; only the generated credential is resolved at runtime.
  - Three-state runtime logic: explicit value → write/overwrite; empty + Secret exists → preserve (no-op); empty + Secret absent → generate once. **Write-once / init-frozen** creds (e.g. the Postgres password — baked into the PVC at first init) must match the PVC if pinned. **Rotatable** creds (e.g. MinIO's `S3_SECRET_ACCESS_KEY` — re-read on restart) rotate by setting the value (the explicit branch overwrites); then restart the consumer.

  Document the Job-bootstrap behavior in `docs/usages.md` when adding or touching such a secret.
