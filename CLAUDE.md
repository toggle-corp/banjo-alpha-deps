# Conventions

- **Helm chart changes require unit tests.** When adding or modifying values, templates, or rendered output in `chart/`, add a corresponding assertion in `chart/tests/*_test.yaml` (run with `helm unittest chart`). Exceptions: pure refactors that don't change rendered output, comment/whitespace-only edits.
- **Helm chart changes require a docs update.** When values, features, or rendered behavior change in `chart/`, update `docs/usages.md` (option reference, examples, and — if relevant — the alpha overlay section). Exceptions: internal refactors with no user-visible change (helper renames, comment-only edits).
- **Generated secrets use the `lookup`-persist pattern — document the GitOps caveat.** Secret templates that default a credential to empty generate a random value once and preserve it across upgrades via a `lookup` on the existing Secret (e.g. `chart/templates/tcpg/secrets.yaml`, `chart/templates/minio/secret.yaml`). `lookup` returns nothing under `helm template`, so under ArgoCD/Flux an empty credential regenerates a **new** value on every sync and drifts from persisted state (the PVC's baked-in Postgres password, MinIO's root creds) — breaking auth. When adding or touching such a secret, keep this pattern and document both escape hatches in `docs/usages.md`: set the value explicitly, **or** have the Application ignore the Secret's `/data` (`ignoreDifferences` + sync option `RespectIgnoreDifferences=true`).
