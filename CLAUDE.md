# Conventions

- **Helm chart changes require unit tests.** When adding or modifying values, templates, or rendered output in `chart/`, add a corresponding assertion in `chart/tests/*_test.yaml` (run with `helm unittest chart`). Exceptions: pure refactors that don't change rendered output, comment/whitespace-only edits.
- **Helm chart changes require a docs update.** When values, features, or rendered behavior change in `chart/`, update `docs/usages.md` (option reference, examples, and — if relevant — the alpha overlay section). Exceptions: internal refactors with no user-visible change (helper renames, comment-only edits).
- **Generated secrets use the `lookup`-persist pattern — document the GitOps caveat.** Secret templates that default a credential to empty generate a random value once and reuse it via a `lookup` on the existing Secret (`chart/templates/tcpg/secrets.yaml`, `chart/templates/minio/secret.yaml`). `lookup` is blind under `helm template`, so under ArgoCD/Flux an empty credential regenerates on **every sync** and drifts from persisted state — breaking auth. Plain `helm upgrade` is unaffected (lookup works on a live cluster). The correct GitOps hatch depends on whether the credential is rotatable, and they must not be mixed up:
  - **Write-once / init-frozen** (e.g. the Postgres password — baked into the PVC at first init, never re-read): set the value explicitly, **or** have the Application ignore the Secret's `/data` (`ignoreDifferences` + sync option `RespectIgnoreDifferences=true`) so it's written once and left alone.
  - **Rotatable** (e.g. MinIO's `S3_SECRET_ACCESS_KEY` — re-read by MinIO on restart): set the value explicitly under GitOps. Do **not** use `ignoreDifferences` here — ignoring `/data` would silently block rotation.

  Document the applicable hatch in `docs/usages.md` when adding or touching such a secret.
